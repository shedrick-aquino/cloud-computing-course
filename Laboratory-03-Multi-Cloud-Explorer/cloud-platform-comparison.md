# Cloud Platform Comparison

## Major Cloud Platform Comparison

| Category | AWS | Microsoft Azure | Google Cloud Platform |
|---|---|---|---|
| **Launch Year** | **2006** – AWS began offering cloud infrastructure services in 2006. | **2010** – Microsoft states Azure launched in 2010. | **2008** – Google launched App Engine in 2008; this is used here as the starting point of Google's public cloud platform history. |
| **Compute Service** | Amazon EC2 | Azure Virtual Machines | Compute Engine |
| **Storage Service** | Amazon S3 | Azure Blob Storage | Cloud Storage |
| **Networking Service** | Amazon VPC | Azure Virtual Network | Google Cloud VPC |
| **Identity Service** | AWS IAM | Microsoft Entra ID / Azure RBAC | Cloud IAM |
| **Primary Strength** | Breadth of cloud services and mature infrastructure ecosystem | Integration with Microsoft enterprise technologies and hybrid environments | AI/data capabilities and Kubernetes/cloud-native workloads |
| **Ideal Organizations** | Organizations needing a broad service catalog, global scale, and many architecture options | Organizations already using Microsoft 365, Windows Server, Active Directory/Entra, .NET, or hybrid Microsoft infrastructure | Organizations focused on AI/ML, analytics, Kubernetes, cloud-native development, and global data workloads |

The service mappings above follow each provider's official product documentation. Google Cloud also publishes a direct AWS–Azure–Google Cloud comparison page that maps generally available services across the three providers.

## Questions

### 1. Which cloud provider offers the broadest range of services?

**AWS** is the strongest answer when the criterion is overall service breadth. AWS describes its platform as providing a broad and deep set of cloud and AI capabilities across a large number of categories, which makes it suitable for many different enterprise architectures.

### 2. Which provider best integrates with Microsoft technologies?

**Microsoft Azure** best fits organizations already using Microsoft technologies. Microsoft Entra ID is integrated with Azure and Microsoft 365, while Azure Virtual Machines support Windows workloads, making migration and identity integration more straightforward for Microsoft-centered environments.

### 3. Which provider is strongest in Artificial Intelligence and Kubernetes?

For this activity, **Google Cloud** is a strong recommendation for AI and Kubernetes workloads. Google Cloud provides Vertex AI for machine-learning and generative-AI workflows, while GKE is Google's managed Kubernetes service; Google's own documentation notes that Kubernetes was developed by Google based on its experience operating large-scale container workloads.

### 4. Which cloud platform would you personally choose and why?

**Sample personal answer — personalize before submitting:** I would choose **Google Cloud** because I am most interested in AI, machine learning, and containerized application development. Vertex AI and GKE give me a clear path for building AI-enabled applications and deploying them using Kubernetes, while Compute Engine and Cloud Storage still provide the basic infrastructure services needed for general cloud workloads.

## Checkpoint 5 – Equivalent Cloud Services

| Service Category | AWS | Azure | GCP |
|---|---|---|---|
| **Virtual Machine** | Amazon EC2 | Azure Virtual Machines | Compute Engine |
| **Object Storage** | Amazon S3 | Azure Blob Storage | Cloud Storage |
| **Identity Management** | AWS IAM | Microsoft Entra ID + Azure RBAC | Cloud IAM |
| **SQL Database** | Amazon RDS | Azure SQL Database | Cloud SQL |
| **Kubernetes** | Amazon EKS | Azure Kubernetes Service (AKS) | Google Kubernetes Engine (GKE) |

Google Cloud's official cross-provider comparison maps comparable AWS, Azure, and Google Cloud services and is useful for validating equivalent service categories. Cloud SQL is Google's managed relational database service, while GKE is Google's managed Kubernetes service.
